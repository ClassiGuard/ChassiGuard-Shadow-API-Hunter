# Microsoft SQL Server design
SQL Server is the **authoritative relational management database**, deployed on Windows. Do not use PostgreSQL. Suggested schema namespaces: `identity`, `inventory`, `policy`, `governance`, `finding`, `integration`, `operation`, `audit`. Tables include Tenant, App, Environment, ApiAsset, ApiRevision, Owner, InventoryMatch, PolicySnapshotMetadata, Node, NodeHeartbeat, Finding, FindingEvidenceRef, ApprovedTestScope, ActiveTestRun, ChangeRequest, Integration, AuditEvent.

Use well-defined keys (uniqueidentifier/bigint appropriate), rowversion optimistic concurrency, UTC datetime2, filtered indexes for active records, migrations with up/down and compatible expand-contract strategy. Tenant isolation enforced in application policy and where appropriate SQL row-level security; test for cross-tenant leakage. Store large raw telemetry in ClickHouse/object storage, not SQL Server. Avoid SQL Server distributed hot paths for per-request ingestion; batch eventual inventory summaries. Encrypted backups, TDE where licensed, key escrow and tested restore. HA via supported SQL Server Always On or failover strategies; license requirements to be verified. Parametrize queries, least-privilege DB principals, migration roles separated from runtime.
